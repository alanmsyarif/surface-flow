# Architecture

## v0.0.1 pipeline

```text
SF_SurfaceFlow
├── Source mask
├── Seed generation
├── Repeat Zone integration
│   ├── sample surface normal
│   ├── tangent gravity
│   ├── stable noise
│   ├── advance
│   ├── closest-surface projection
│   └── trail accumulation
└── Points to Curves output
```

The master group is generated by `surface_flow/build_nodes.py` so changes remain reproducible in Git rather than existing only inside a `.blend` binary.

## Why trail points instead of extending curves in the loop

Appending control points to many curves individually is awkward in a field-based node graph. The implementation therefore records every path sample as a point cloud with two stable attributes:

- `sf_id`: path identity
- `sf_age`: integration order

After the Repeat Zone, **Points to Curves** groups points by `sf_id` and sorts them by `sf_age`. This keeps the iterative core simple and makes the final topology deterministic.

## Surface attachment

The MVP uses **Geometry Proximity** to project each advanced tip back to the closest face of the target mesh. That is deliberately chosen over raycast-only attachment because nearest-surface projection is less likely to fail on strongly curved features.

This is not yet enough for true physical adhesion. Later milestones will add a support metric and controlled detachment.

## Data attributes

| Name | Type | Domain | v0.0.1 use |
|---|---|---|---|
| `sf_id` | int | point | curve grouping |
| `sf_age` | float | point | point sorting / future reveal |
| `sf_normal` | vector | point | surface offset and future support |

Planned:

- `sf_weight`
- `sf_accumulation`
- `sf_support`
- `sf_wetness`
- `sf_resistance`

## Performance strategy

The MVP is designed around hundreds of paths and tens of iterations, not millions of fluid particles. Keep preview density and step count low. Final-film work should be separated from path integration so appearance changes do not force unnecessary regeneration of the network.
